# Research: upstream krau/SaveAny-Bot fork-drift analysis

Source: researcher agent, 2026-10-24.

## Headline

**Fork is fully synced with upstream today**: merge-base of fork `main` and `upstream/main` is `92e6072` = upstream HEAD (2026-10-08). Upstream 0 ahead; fork 40 ahead. No rebase debt. Real risk is future drift: upstream is active (~48 commits Jun–Oct 2026, release every 1–3 weeks, latest v0.63.0) and roadmap #251 plans a **gotgproto replacement** (gogram / hard fork / raw gotd — sessions + handler API break) and a web UI. Upstream already has `/watch`+`/unwatch`+`/lswatch`+`/watch notify` (PR #247) and `/tasks`; upstream has NO history ledger, NO catch-up cursor, NO per-watch storage.

## Upstream schemas (database/model.go; AutoMigrate in database/db.go)

- `WatchChat` — `UserID uint`, `ChatID int64`, `Filter string` — nothing else (no storage/dir/cursor; no index on chat_id despite per-message query).
- `User` — ChatID, Silent, DefaultStorage, DefaultDir, Dirs, ApplyRule, Rules, WatchChats, WatchNotify, FilenameStrategy, FilenameTemplate, ConflictStrategy.
- `Dir` — UserID, StorageName, Path. `Rule` — UserID, Type, Data, StorageName, DirPath.
- Ledger tables (`TelegramSavedFile`, `SavedFileDedup`, `PendingTask`), resume, media filter = **fork-only**.

## i18n conventions

go-i18n/v2 + YAML, embedded from `common/i18n/locale/` — exactly `en.yaml` + `zh-Hans.yaml` (zh-Hans default). Keys generated by `cmd/geni18n` into `i18nk/keys.go` (`bot.msg.<area>.<snake>` → `BotMsg<Area><Pascal>`). Both locales must stay in lockstep or gen fails. Template data `{{.Error}}` style. Commands registered in `CommandHandlers` slice (register.go) which feeds help.

## Recommendations adopted by this plan

1. Schema additions additive: nullable columns on `WatchChat` (`StorageName`, `DirPath`, `LastMessageID`) — upstream has no such concepts, collision unlikely; AutoMigrate tolerates.
2. `/status` must not fork the `/tasks` concept — build on `core.GetRunningTasks`/`GetQueuedTasks`; append new fork commands at the END of `CommandHandlers` so upstream insertions merge cleanly.
3. `/history` ledger isolated in own files (already true) — `model.go` stays the only hand-merge hotspot (fork already added `MediaFilter`/`MediaType` there).
4. Keep fork logic in small separately-named functions/files; distinct column names (`media_type` pattern).
5. Confine gotgproto types to handler boundary; catch-up/status/history core logic in plain packages (roadmap #251 migration insurance).
6. Match conventions: `Unscoped()` hard deletes, xid task IDs, gorm.Model embedding, i18n const for every user-visible string (both locales).
7. Re-sync upstream at least every release (1–3 weeks).
